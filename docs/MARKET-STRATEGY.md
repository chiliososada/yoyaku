# 予約システム SaaS — 日本市場攻略ロードマップ

> 基于代码库现状的实盘评估（2026-07）。目标：在日本本土店家市场杀出血路。
> 结论先行：**产品已过"可售卖"线，胜负手在垂直场景选择 + "帮店家赚钱"的功能层 + 信任资产。**

---

## 0. 现状盘点（已完成的资产）

- **架构**：多租户 SaaS（平台 / 商家 / 员工三层 RBAC），29 个数据模型，约 1.7 万行 TypeScript，138+ 测试全绿
- **预约引擎**：营业时间 / 祝日 / 临时休业 / 员工排班 / buffer / 多时段占用 / 各级容量 / 受付期限
- **防超卖**：advisory lock + 事务内容量再判定 + GiST 排他约束 + 幂等键，多层防御，并发实测通过
- **LINE 闭环已通**：LIFF 内预约、顾客 LINE 确认 / 24h 提醒 / 取消 / 改期通知、店家 LINE 通知、follow/unfollow 处理
- **计费**：Stripe SaaS 订阅（30 天试用 / 锁定 / Webhook 幂等），随时可开闸收费
- **经营功能**：月次报表（売上/客单价/指名率/新规/回访）、员工排名、CSV 导出、日程时间轴、顾客カルテ、休眠客户检测、QR 物料、审计日志
- **顾客自助**：预约 / 取消 / 改期（token 链接）
- **运营成熟度**：生产运行中（yoyaku.arcs-ai.com）、SMTP + SPF/DKIM/DMARC 真实送达、每日备份、法务页面、17 截图自助指南

**判断**：交易层（省事功能）已齐。从"代码"到"可收钱产品"的距离已走完 90%。

## 1. 竞争逻辑：不拼"省事"，拼"赚钱"

预约 SaaS 的付费意愿分水岭：

| | 帮店家**省事** | 帮店家**赚钱** |
|---|---|---|
| 内容 | 接预约、发提醒、看报表 | 减少 no-show、提高稼働率、增加回头客 |
| 竞争格局 | RESERVA / Airリザーブ 免费送 | 竞品收 ¥10,000〜30,000/月，或做得很弱 |
| 定价天花板 | ¥3,000/月 | ¥10,000〜30,000/月 |
| 本产品位置 | ✅ 已完成 | ← **主攻方向** |

店主的账：每月 5 单爽约 × 客单价 ¥5,000 = ¥25,000 损失。能堵住这个洞的工具，收 ¥10,000/月不算贵。

正面战场上"功能齐全"毫无意义（免费大厂在那里）。杀出血路只有一条路：
**选一个巨头没占住的垂直场景 → 做 2-3 个免费竞品结构上给不了的功能 → 用信任资产补小公司的短板。**

## 2. 功能清单（按优先级）

### 第一梯队：钱的痛（直接决定成交，约 1 个月）

| # | 功能 | 说明 | 工作量 |
|---|---|---|---|
| 1 | **预约定金 / 事前决济** | 预约时收定金或全款，取消政策自动执行（期限内退款 / 过期没收）。Stripe 基建可复用 | 2-3 周 |
| 2 | **爽约费自动扣款** | 预约时登记信用卡（不扣款），無断キャンセル时按政策自动扣。顾客无摩擦、店家利益全保。竞品普遍弱，HPB 做不了 | 定金基础上 +1 周 |
| 3 | **キャンセル待ち候补队列** | 满枠登记候补，放出枠自动 LINE 推送先到先得。直接提高稼働率。slot 引擎 / 取消事件 / LINE 推送全部已有 | ~1 周（性价比最高） |
| 4 | **回数券 / 月谢 / 会员订阅** | 脱毛、エステ、健身全靠这个模式。预付 = 现金流前置 + 锁客。垂直深耕的台柱 | 2-3 周 |

### 第二梯队：复购引擎（决定留存续费，约 1 个月）

已有 outbox + scheduledAt 定时机制，以下均为"顺手"级别（各 3-5 天）：

| # | 功能 | 说明 |
|---|---|---|
| 5 | **来店后自动感谢 + Google 口コミ依頼** | 来店标记 → N 小时后 LINE 感谢 + Google 评价链接。评价数直接影响 Google Maps 排名（MEO），日本店家刚需中的刚需 |
| 6 | **休眠客户自动唤回** | 已有休眠检测（列表），加自动 LINE 推送 + 优惠券 → 从报表变成赚钱机器 |
| 7 | **生日 / step 配信、分群群发** | 按来店史 / 标签筛选群发。LINE 免费额度 200 通/月，超额费用可设计为收费项 |

> 销售叙事升级：从"予約システム"变成 **"リピート率を上げる装置"**。

### 第三梯队：日本获客渠道功能

| # | 功能 | 说明 | 工作量 |
|---|---|---|---|
| 8 | **预约经路分析** | 每笔预约标记来源（Instagram / Google / LINE / 店头 QR / 回头客），月报显示渠道贡献。`BookingSource` 枚举已在 schema 中 | 增量很小 |
| 9 | **Google 日历双向同步 + iCal** | 个人事业主硬需求（私人日程挡预约枠），也是从 STORES 予約 抢客户的搬家理由 | 中等 |
| 10 | **品牌定制预约页 + 独自域名** | 颜色 / 照片 / 域名定制，做出"我店官网预约"体感。高单价沙龙在意 | 中低 |
| 11 | **サロンボード顾客 CSV 导入** | 打美容室的入场券。故事："新客让 HPB 吸，二回目以降转自己 LINE 直约，省 20% 抽成" | <1 周 |

### 第四梯队：杀手锏（人手不足叙事，蓝海所在）

| # | 功能 | 说明 |
|---|---|---|
| 12 | **智能锁联动** ⭐ | 预约成立 → 自动发行仅预约时段有效的开门码（RemoteLOCK / SESAME / Akerun 均有 API）。无人店业态的核心部件 |
| 13 | **AI 应答** | 营业时间外 LINE 提问自动回答；漏接电话自动回短信 + 预约链接（转送号码 + Twilio，几天可通）。"受付を雇わなくていい"是 2026 年日本最好卖的故事 |

## 3. 明确不做 / 做不了（避免浪费时间）

| 项目 | 原因 | 现实替代 |
|---|---|---|
| Reserve with Google（Google で予約） | 需 Google 官方 scheduling partner 资质，小团队进不去 | GBP 挂预约链接 + 预约页结构化数据 |
| Instagram 官方预约按钮 | 需 Meta 合作伙伴资质 | link-in-bio 落地页 + 经路追踪（#8 闭环） |
| HPB / サロンボード官方联动 | 官方 API 不存在，第三方同步是灰色手段 | CSV 顾客导入（#11） |
| POS / 收银 / 会计 | 重、Square / Airレジ / STORES 深耕 | 需要时做集成，不自建 |
| 原生 App | LIFF + 网页够用，App 是维护黑洞 | — |
| 通用门户 / marketplace | 与 Hot Pepper 正面刚，烧钱无底洞 | — |
| 医疗级电子カルテ | 法规深水区 | 除非 all-in 医疗垂直 |

## 4. 主攻方向

### 主攻：无人 / セルフ型店舗 ⭐
（個室サウナ、セルフ脱毛、セルフエステ、インドアゴルフ、レンタルスペース）

- 市场在涨：人手不足宏观趋势推动业态爆发
- 无价格亲民的垂直霸主：hacomono 盯健身房且 ¥30,000+/月起
- 痛点极清晰：不想雇前台；¥15,000〜30,000/月只是前台人力零头 → 付费意愿高
- **功能拼图 60% 已有**：时段占用引擎 + 事前决济 + 会员/回数券 + 智能锁 + LINE

### 次选：高单价沙龙（脱毛 / エステ / パーソナルジム）
爽约费自动扣款 + 回数券直接命中命门；竞争存在但碎片化。

### 侧面打：美容室
最大市场但壁垒最厚（HPB 生态、Beauty Merit、かんざし 层层把守）。
**不正面刚**，只讲一个故事："新客让 HPB 吸，二回目以降转自己的 LINE 直约"。入口 = CSV 导入（#11）。

## 6. 与功能同权重的任务：信任资产

日本店主签约前必看"別の店も使ってる"的证据。

- **導入事例 3-5 件**：前几家免费也要拿下，要到实名 + 店铺照片 + 一句感想放官网
- 没有事例页，功能再强也没人敢当第一个吃螃蟹的人
- 这与写代码是**同等优先级**的任务

---

## 7. 总原则

1. 产品已过"可卖"线，**闭门加功能的边际收益正在递减**
2. 第一梯队做完（约 1 个月）就去铺 5-10 家真实店铺
3. 付费客户提的需求和这份清单打架时——**听付钱的人的**。这份清单只保证第一步不踩空
